# Translations (EN / FR / IT / DE)

> **Status:** French, Italian and German copy are AI drafts pending native-speaker review.

## How it works

- Every page lives under a locale prefix: `/en`, `/fr`, `/it`, `/de` (e.g. `/fr/la-brigue`).
- Visiting a URL without a prefix (e.g. `/apartment`) redirects via `src/proxy.ts` using, in order: the `NEXT_LOCALE` cookie (set by the language dropdown), the browser's `Accept-Language`, then English.
- All visible text, image alt text and page metadata come from JSON dictionaries in `src/i18n/dictionaries/`.
- Supported locales, display names and link helpers are in `src/i18n/config.ts`.

## Editing copy

1. Open the dictionary for the language, e.g. `src/i18n/dictionaries/fr.json`.
2. Change the string value only — keep keys and array order identical across all four files (arrays are matched to images by position).
3. `en.json` is the source of truth for structure. If a key is added there, add it to `fr.json`, `it.json` and `de.json` too; the TypeScript build fails if any language is missing a key.
4. Use typographic apostrophes (`’`) to avoid escaping.

Headings with a coloured accent are split into `titleLead` / `titleAccent` (and sometimes `titleTail`); they are rendered with a space between each part.

## Contact form

The form sends the visitor's language with each enquiry. Validation errors are localized in `src/app/api/contact/route.ts`, and the notification email subject is prefixed with the language code (e.g. `[FR]`) so you know which language to reply in.

## Adding a language

1. Add the code to `locales` and `localeNames` in `src/i18n/config.ts`.
2. Create `src/i18n/dictionaries/<code>.json` (copy `en.json` and translate).
3. Register it in `src/i18n/dictionaries.ts` and add messages for it in `src/app/api/contact/route.ts`.
